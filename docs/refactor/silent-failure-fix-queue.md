# Silent-Failure Fix Queue (Phase 2 Triage)

Generated by hand 2026-04-28 from `docs/refactor/silent-failure-inventory.md`
(1988 findings across 12 patterns).

This file orders findings into discrete **fix waves**. Each wave:

- Tackles ONE bug class end-to-end (not cherry-picked instances)
- Lands as one or more focused commits
- Closes with: build + test + doctor + smoke green
- Locks in a doctor verifier so the class can't regress (Phase 4)

## Fix wave order

The order optimizes for: highest signal first, least risk first, and
side effects (a fix in wave N often eliminates findings in wave N+1).

### Wave A — Tear down `_deps.ts` setter slots (CRITICAL × 46)

**Pattern**: `unwired-setter-slot` (audit 01)

**What it is**: 46 `_deps.ts` setter slots have paired getters with real
readers but ZERO writers. Every reader gets the safe-default no-op.
Exact bug class behind the ralph-loop hook regression.

**Approach (aggressive)**:
For each of the 46 slots:
1. Locate the real implementation (where the V7 migration moved the
   function to). Usually `@claude-code/storage`, `@claude-code/agent`,
   `@claude-code/app-host/bootstrap/state`, etc.
2. Inline-import the real impl directly in the consumer file. Skip the
   `_deps.ts` placeholder entirely.
3. Delete the slot, default state var, getter, and setter export.
4. Verify build + test after every ~5 slots cleared.

If a slot's reader is in `packages/config/plugin/` and the real impl
lives in a package that would create a cycle, fall back to **wire it in
`packages/app-host/src/runtime/installPluginBindings.ts`** instead. This
is the conservative half of "aggressive teardown".

**Expected outcome**: ~46 CRITICAL findings → 0. Likely also resolves
several MEDIUM dual-storage-divergence findings (audit 04) as the same
slots disappear.

**Verifier to lock in (Phase 4)**: `verify-deps-setters-wired`
(already drafted at `scripts/verify-deps-setters-wired.ts`).

### Wave B — Eliminate optional-chain-on-required (HIGH × 97 + 1)

**Pattern**: `optional-chain-on-required-binding` (audit 03) +
`optional-method-no-guard` (audit 09)

**What it is**: `getXxxBindings().method?.()` where the contract type
declares `method` as required. The `?.` masks "binding not installed";
silently degrades to undefined.

**Approach**:
Three options per finding:
1. **Drop the `?.`** — if the contract really requires the method, it's
   a precondition violation, not graceful degradation. Hard error is
   strictly better than silent default.
2. **Make the contract field actually optional** (`method?:`) — if the
   caller's degradation IS intentional. Then the `?.` is fine.
3. **Add a guard** — `if (!method) throw ...` then call without `?.`.

The right answer depends on the contract author's intent; needs file-
by-file review. Group by file: a single contract often has 5-10 fields
and the same answer applies to all.

**Expected outcome**: 97 HIGH → 0. One finding may produce edits in
several call sites (multi-caller contracts). Total commits ~10-15.

**Verifier to lock in (Phase 4)**: `verify-optional-chain-on-required`.

### Wave C — Audit MEDIUM dual-storage divergences (MEDIUM × 36)

**Pattern**: `dual-storage-divergence` (audit 04)

**What it is**: Verb pairs (get/set, register/clear) where reader and
writer live in different packages. Most are likely intentional (a host
binding bridges them), but the ralph-loop bug was hidden in a sibling.

**Approach**:
For each finding:
1. Confirm the two endpoints share a backing store. If yes, mark as
   "by-design" with a comment in code.
2. If they don't, that's a real bug — decide which side wins, fix the
   other.

Wave A may resolve many (any pair where the loser is a `_deps.ts`
slot). Re-run audit 04 after Wave A to see the residual.

**Verifier to lock in (Phase 4)**: `verify-dual-storage-paired`.

### Wave D — MEDIUM `??` defaults in critical paths (MEDIUM × 110)

**Pattern**: `nullish-coalesce-critical-path` (audit 06)

**What it is**: Call chains like `something() ?? []` in critical-path
files (agent, permission, provider, host). When `something()` returns
null due to a real bug (not absence), the `??` masks it.

**Approach**:
File-by-file. For each `?? default`:
1. Read the LHS function — does it document "returns null when X is
   absent"?
2. If yes, default is correct. Add a brief comment explaining why.
3. If no (LHS may return null on real failure), replace with explicit
   handling: `if (x == null) throw ...` or log + recover.

Mostly comment-adding; keeps blast radius small.

### Wave E — Empty catch blocks (LOW × 99)

**Pattern**: `empty-catch` (audit 05)

**Approach**:
Add a single-line comment to each empty catch explaining why the
exception is acceptable. If no good reason exists, add `logError(e)` or
rethrow. Touch-once-and-document; don't try to redesign error handling.

This is mostly a hygiene pass, low risk.

### Wave F — Always-false feature flags (LOW × 495)

**Pattern**: `always-false-feature-flag` (audit 08)

**What it is**: `feature('X')` callsites where X is never enabled in
dev or build. Branch is dead unless an env var is set.

**Approach**:
1. Group by flag name; many flags have 10+ callsites each.
2. For each flag, decide:
   - **Keep**: if it's a real opt-in feature (DAEMON, BG_SESSIONS,
     BRIDGE_MODE etc.). Add to `docs/feature-flags.md` as documented
     opt-in.
   - **Delete**: if the flag is leftover from V7 ablation experiments
     or removed features. Delete the branch entirely.
3. Doctor verifier: every `feature('X')` flag must be documented in
   `docs/feature-flags.md` OR enabled in dev/build.

This is the largest single surface (495 sites) but most groupable.

### Wave G — `as any` review (MEDIUM × 364)

**Pattern**: `type-cast-trap` (audit 10)

**What it is**: `as any` escapes. V7 has heavy decompiled-boilerplate
casts.

**Approach**:
1. Skip `as any` in clearly decompiled code (React Compiler `_c()`
   stuff, Ink internals).
2. For the rest, attempt to replace with a precise type or
   `as unknown as Foo`. The latter at least surfaces "this is a bypass".
3. Add a doctor ratchet: total `as any` count cannot grow.

### Wave H — `require()` fallback patterns (MEDIUM × 272)

**Pattern**: `require-fallback-to-stub` (audit 11)

**Approach**:
1. Verify each require target exists at runtime. Most are
   feature-gated dynamic loads (BG_SESSIONS, DAEMON), legitimate.
2. For ones whose target SHOULD always exist but is wrapped in
   try/catch — that's the bug. Investigate and either remove the
   wrapper or fix the require path.

### Wave I — `await-generator-misuse` MEDIUM (4)

Audit 02 dropped to 4 MEDIUM findings (false positive risk after the
`hasLocalShadow` filter). Hand-verify each in 10 min.

### Wave J — Stub-return-only review (LOW × 26)

Audit 07 has 26 functions whose body is just `return null/[]`. Most
are intentional placeholders; verify each is intentional or delete.

### Wave K — Module-level null state (MEDIUM × 4)

Audit 12 has 4 module-level `let X: T | null = null` declarations
without an in-file writer. Trace whether the writer (likely external
host binding) actually runs at startup.

## Severity reassignment after Wave A

Wave A is the BIG win — 46 CRITICAL → 0 plus likely 10-15 collateral
MEDIUM/HIGH cleared. Re-run `bun scripts/audit-silent-failures/run-all.ts`
after Wave A to refresh the baseline; the inventory will shrink
sharply.

## What we are explicitly NOT doing

- Auto-fixing things. Every fix has a human commit message explaining
  the call.
- Adding new patterns mid-flight. The 12 audits are the contract for
  this cleanup. New patterns wait for the next round.
- Touching React Compiler decompiled boilerplate (`_c()` calls). It's
  noise filtered out by the inventory.
