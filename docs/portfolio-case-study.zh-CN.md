# Claude Code Best：金融科技实习作品说明

这个项目对金融实习的价值主要落在工程基础设施、模型治理和自动化风控，而非证券定价或财务建模。投递量化研究、投行或传统公司金融岗位时，它只能作为第二项目；投递金融科技、数据平台、模型风险、交易基础设施或 AI 工程岗位时，它可以成为主项目。

## 简历版项目描述

独立维护跨平台终端智能体 `ccb`，在来源重建代码上完成模块化重构、多模型供应商路由、后台多智能体调度与自动更新；建立 80 余项架构门禁、万级行为测试及类型/静默失败单向债务预算，并为 macOS、Linux、Windows 发布独立二进制。

设计自动化上游变更取证流水线：定时检测新二进制，完成 Bun 模块提取、跨版本指纹匹配、结构化差异与 LLM 语义报告，将“解码—分析—移植—验证”分层记录，阻止失败任务以成功状态进入维护决策。

强化软件供应链：发布前重跑精确源码验证，生成 SHA-256、748 组件 CycloneDX SBOM 与 GitHub/Sigstore 来源证明；将 Actions 固定到完整提交 SHA，并加入跨平台原生启动、依赖漏洞审查和 nightly 故障 issue 恢复闭环。

## 面试时应主动说明

项目基线来自 Claude Code 2.1.88 sourcemap 的社区重建，原始产品及其代码不属于本人；个人贡献从独立维护、架构重构、功能移植、测试治理、发布工程和逆向更新流水线开始。仓库缺少可明确支持再分发的上游许可证，因此展示时应保留 attribution 与权利风险说明。

最有说服力的现场演示，是展示一次失败的自动分析如何留下 metadata、返回非零状态并触发通知，再展示 nightly 检查如何从失败 issue 到恢复关闭。这类“系统如何知道自己不知道”的能力，与金融系统中的数据质量、模型风险、审计轨迹和故障隔离具有直接同构关系。

## 仍需搭配的金融项目

为了补足金融领域信号，建议另做一个可复现的事件驱动研究或风险监控项目：使用公开市场数据，明确时间戳、复权、幸存者偏差和交易成本，提供 walk-forward 验证、基准比较、失效条件及数据血缘。它负责证明金融判断；`ccb` 负责证明复杂系统工程和治理能力。两者合在一起，简历才会既有河床，也有水流。
